Overview

A Gradio dashboard for training and sampling a two-stage conditional diffusion model of ion-channel current traces.

The app has two panels. Train fits a diffusion model to your real recordings (or synthetic toy data) and shows the loss curve, a sample trace and an amplitude histogram updating live as it trains. Generate uses a trained model to simulate a channel-gating sequence from a transition matrix, then dresses it with the model's learned noise, and exports the result as a Parquet file.

The model is trained on your idealisation (the number of open channels at each sample) paired with the matching real current trace, and learns to generate a plausible noisy current for a given idealisation.

Running the app

First setup a custom environment, follow the readme and the requirements.txt.

Then, from a terminal, in the folder containing diffusion_app.py and diffusion_103.py:

python diffusion_app.py

The Gradio terminal displays a local URL, open this in your browser. There's no separate install step covered here beyond having the usual packages (torch, gradio, pandas, numpy, matplotlib) available.

Typical workflow

  1. Put your recordings (.csv or .parquet) in a folder, or tick Force synthetic toy data to try the app without real data first.
  2. Set the CSV folder field to that folder's path.
  3. Click Scan input -> reads your files and sets a sensible range on the how slow slider.
  4. Leave defaults or adjust parameters (see below), then click Start training.
  5. Watch the loss curve, sample trace and histogram update every Update every N steps steps. A checkpoint is saved automatically at the end of every epoch.
  6. Once training finishes, switch to the Generate panel, set your transition matrix, and click Generate & download Parquet.

Train panel -> slow-phase (envelope)

Ion current often has a slow-moving envelope on top of the fast noisy detail. Ticking this on trains the model in two stages: a coarse model of the slow envelope first, then a fine model of the detail, conditioned on both the idealisation and the coarse envelope. Leaving it off trains a single stage, conditioned on the idealisation alone.

ControlWhat it does
Model a slow phaseTurns the two-stage cascade on/off.
How slowSamples averaged into each envelope step. Scan input sets this slider's usable range for your data.
Slow-phase training ×Multiplier on Epochs for how long the coarse stage trains, relative to the fine stage.
Decimation phasesNumber of phase-offsets used when decimating for the coarse stage, a form of data augmentation. 1 turns it off.

"Data too short for 'how slow' = N", the decimated page is shorter than the coarse model's window. Lower the how slow slider, or click Scan input to reset it to a value your data can support.

Train panel -> resume & checkpoints

The When I press Start option chooses between Start fresh and Resume from last checkpoint. Resuming re-loads the architecture (width, diffusion steps) from the saved checkpoint, your slider values for those are ignored if you're resuming, but learning rate, window settings and epoch count still come from the form.

Every epoch, the model is checkpointed to ion_channel_diffusion_model.pt (an atomic save, so a crash mid-write can't corrupt it). When a training run finishes, that checkpoint is also archived under a timestamped filename with a matching .txt file describing exactly how it was trained.

Resuming only works if the new run's conditioning matches the checkpoint's (i.e. slow-phase on/off is the same). If it doesn't match, the app tells you in the status box and starts fresh instead of failing.

Generate panel -> transition matrix

The Markov chain governing channel state transitions. Each row is the probability of moving from that state to every other state, and should sum to 1 (the app renormalises rows for you if they don't).

ControlWhat it does
Transition matrixEditable grid -> resize by adding/removing rows and columns.
Open-state indicesComma-separated list of which states count as "open" (current flows), e.g. 3,4 (the default).
Number of channelsHow many independent copies of this chain to simulate together.
Preview idealisationSimulates a short idealisation and plots open-channel count over time, so you can check the matrix behaves as expected before committing to a long, slow generation run.

Generate panel -> fit to a seed record

Fits the transition matrix to the idealisation of one of your recordings, so generated data can follow that record's kinetics. Zeros in the current matrix stay zero, so the matrix you enter sets the model topology; non-zero entries are the starting values. The fit maximises the likelihood of the idealisation sequence, and the result replaces the matrix in the grid.

ControlWhat it does
Seed page indexWhich file in the CSV folder to fit (0 = first).
Channels in recordNumber of channels in that record; 0 infers it from the maximum open-channel count.
Samples to fitHow many samples from the start of the record are used.
RestartsNumber of fits from different starting points; the one with the highest log-likelihood is kept.
Dirichlet priorSmall pseudo-count added to transition counts, which keeps rarely seen transitions from fitting to exactly zero. 0 gives the plain maximum-likelihood fit.
Fit matrix to seed recordRuns the fit. The fit status box reports the log-likelihood, BIC, iterations, each restart's log-likelihood, and the mean dwell per level for the real record and for a simulation from the fitted matrix.

Generate panel-> output file

Clicking Generate & download Parquet writes generated_dataset.parquet with three columns:

ColumnContents
TimeSeconds, assuming a 10 kHz sample rate.
ChannelsSimulated open-channel count at each sample (the idealisation).
Noisy CurrentThe model-generated current for that idealisation.

If the checkpoint is a two-stage (slow-phase) model, generation runs the coarse envelope pass first, then the fine detail pass conditioned on it, you'll see the progress bar split roughly 40/60 between the two.

Troubleshooting

MessageWhat's happening
Data too short for 'how slow' = NYour decimated pages are shorter than the coarse stage's window. Lower how slow or re-run Scan input.
No trained model at '...'No checkpoint exists yet at that path -> train first.
"conditioning differs; starting fresh"You asked to resume, but the saved checkpoint's slow-phase setting doesn't match the current form, so a fresh model was started instead.
"Synthetic fallback: no CSVs in ..." in the status boxNo CSV/Parquet files were found in the given folder, so synthetic toy data was used instead, check the folder path. We created a little "gotcha" here, if you make a mistake you can find you are training the example not your actual data!

Glossary

IdealisationThe discrete channel-state sequence (how many channels are open at each sample), as opposed to the noisy continuous current.
EnvelopeThe slow-moving amplitude trend underlying the fast noisy detail in a current trace.
Coarse / fine stageThe two steps of the slow-phase cascade: coarse models the envelope, fine models the detail on top of it.
eps-MSEMean squared error between the true and predicted noise at each diffusion step, it is the training loss.
MMDMaximum Mean Discrepancy, a distributional distance between real and generated samples, printed to the terminal during training.
DecimationDownsampling by averaging (or by keeping every Nth point) to produce a coarser, shorter view of a trace.
